# Finora

Finora is a personal stock-watchlist dashboard built with React and Vite. Users sign in, add ticker symbols to a private watchlist, and see each stock's latest daily percentage movement from Alpha Vantage.

## Features

- Clerk sign-in, sign-up, and account controls
- Per-user watchlists stored in Supabase
- Daily stock performance fetched from Alpha Vantage
- Responsive interface for desktop and mobile screens
- Vite development server with ESLint and production builds

## Tech Stack

- React 19
- Vite 8
- Clerk React for authentication
- Supabase JavaScript client for persistence
- Alpha Vantage REST API for market data
- ESLint for code quality checks

## Getting Started

### Prerequisites

- Node.js 18 or newer
- A Clerk application
- A Supabase project
- An Alpha Vantage API key

### Installation

```bash
npm install
cp .env.example .env
```

Fill in `.env` with your own credentials, then start the development server:

```bash
npm run dev
```

Open the local URL printed by Vite, usually `http://localhost:5173`.

## Environment Variables

Vite exposes variables prefixed with `VITE_` to the browser. Do not commit `.env`; it is ignored by Git. Use `.env.example` as the setup reference.

| Variable | Purpose |
| --- | --- |
| `VITE_CLERK_PUBLISHABLE_KEY` | Clerk publishable key used by `ClerkProvider` |
| `VITE_ALPHA_VANTAGE_KEY` | Alpha Vantage API key for daily time-series data |
| `VITE_SUPABASE_URL` | Supabase project URL, without `/rest/v1` |
| `VITE_SUPABASE_ANON_KEY` | Supabase anonymous client key |

The Supabase client requests a Clerk session token using the `supabase` JWT template. Configure that template in Clerk and connect it to Supabase before testing authenticated database requests.

## Supabase Setup

Create a `watchlist` table with at least these columns:

```sql
create table public.watchlist (
  id bigint generated by default as identity primary key,
  user_id text not null,
  symbol text not null,
  created_at timestamptz default now()
);
```

Enable Row Level Security and add policies that restrict rows to the authenticated Clerk user. The exact policy expression depends on the claims configured in your Clerk JWT template, so verify the claim mapping in Supabase before enabling production access.

## Data Flow

1. Clerk authenticates the user and provides a session.
2. `StockList` creates a Supabase client with the Clerk `supabase` JWT template.
3. Watchlist rows are read, inserted, or deleted for the signed-in user's ID.
4. Each ticker is sent to Alpha Vantage to calculate the latest daily change from the two newest closes.

## Notes and Limitations

- Alpha Vantage rate limits can affect how quickly multiple watchlist entries load.
- The current add-stock flow expects a valid ticker symbol and relies on the upstream APIs for validation.
- The app currently displays daily percentage movement rather than live market prices.
- API keys should be rotated if they have ever been committed to a public repository.
